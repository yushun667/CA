# 文档规范审查

Markdown、目录索引、规划、架构、决策、问题记录及其他说明性文件进入 commit 前必须完成本审查。

## 审查清单

- 项目文档与实质记录遵守 [双语契约](../i18n.md)，本次涉及的语言对和一致性记录同步；冻结档案遵守档案规则。
- 内容反映当前事实；理由住决策、历史住作废决策或归档、当前状态住规划。
- 一个事实只有一个权威位置，其他位置使用相对链接，不复制整段规则。
- 根 `AGENTS.md` 仍是短入口；目录 `AGENTS.md` 只描述本层并给出读取条件。
- 每个 Git 可见维护目录都有 `AGENTS.md`，父索引链接直接子目录；移动或删除后无失效入口。
- 只保留任务需要的细节；所有文件满足 `../governance.json` 的字符和行数上限。
- 从根到任一目录的自动 `AGENTS.md` 指令链和根到单篇管理文档的按需加载链都满足治理预算。
- 链接、路径、命令、标题和状态互相一致；没有未解析的 `{{...}}` 模板标记。
- 文档改动与当前 commit 是同一逻辑目的，最终暂存差异已重新检查。

## 超限处理顺序

先删除重复，再把细节下沉到相关子目录，最后按主题拆分并更新索引。不得以“内容重要”为由直接扩大预算。
