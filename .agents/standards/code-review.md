# 代码规范审查

代码、脚本、测试、行为配置或构建逻辑进入 commit 前必须完成本审查。审查后如有实质修改，原审查失效并重新执行。

## 审查清单

- **范围**：差异只服务于当前 commit 的一个逻辑目的，没有顺手重构或无关格式化。
- **正确性**：正常路径、边界、失败路径和状态变化符合需求；没有静默吞错。
- **契约**：接口、数据格式、兼容性和副作用有明确边界；相关架构或决策已同步。
- **安全与隐私**：输入、权限、凭据、日志和依赖风险得到与变更相称的检查。
- **资源与配置**：注册与解除、创建与释放成对，按项目语言保证异常路径释放；缺配置或引用在最早可判定点明确报错。
- **可维护性**：命名和结构表达职责，没有无来源的复杂度、重复事实或过期注释。
- **测试**：行为变化有聚焦验证；运行了仓库实际存在的测试、类型、lint 或构建命令。
- **差异复核**：审查的是最终暂存差异，而不是较早版本。

## 通过标准

所有适用项有证据，命令结果已报告，已知未解决风险明确且不阻止本次目标。技术栈专用命令应记录在最接近代码的目录 `AGENTS.md`，不得在本文件猜测。
