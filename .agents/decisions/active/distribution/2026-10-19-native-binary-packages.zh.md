# 决策：原生安装包同时保留命令行、MCP 与网页

Status: active
Date: 2026-10-19

## 背景

用户要求 Linux、Windows 与 macOS 直接可运行的原生安装包，安装后命令行、MCP 与
网页均可用，双击默认打开本机浏览器。既有 Python/wheel 与 DSH 部署仍是有效安装路径。

## 决策

- 在各受支持系统与架构上分别原生构建 PyInstaller 目录包，随包携带 Python、匹配的
  Clang 绑定/动态库、DuckDB、schema 与网页资源，不要求用户准备 Python 环境。
- 冻结入口仅在无参数时默认进入 `desktop`；显式命令保留既有 CLI 契约，特别是 MCP
  stdio 只将诊断写入 stderr。先初始化多进程再分派命令，避免冻结后的 worker
  启动另一个桌面服务。
- 桌面启动统一后端并绑定回环地址，打开浏览器，数据存入系统用户数据目录或
  `CA_DATA_DIR`。默认首启创建空索引，显式指定的数据库必须已存在。
  Windows 监听使用独占绑定，防止端口选择使浏览器混入共享该端口的旧服务。
  数值本机地址绑定不做反向 DNS，避免离线或名称解析阻塞卡住启动。
- 分发 Windows Inno Setup、Linux Debian 与 macOS pkg 安装器，以及完整便携目录
  压缩包和 SHA-256 校验和。原生 GitHub Actions 任务对产物做冒烟测试，不发布 Release。
- 首批目标是 Windows x64、Linux x64 与 macOS x64/arm64。构建基线和用户契约统一放在
  [二进制指南](../../../../docs/binaries.zh.md)。

## 原因

原生包满足无需 Python 安装的需求，并保持同一个可执行文件供用户和 agent 客户端使用。
目录包让原生依赖与数据文件集中，便于调查缺少资源的问题。分别原生构建可暴露各平台
故障，无需假定交叉编译可行。用户数据放在安装目录之外，替换或卸载程序不会销毁索引。

## 考虑过的替代方案

- **只提供 wheel 与私有 venv：**保留给源码/DSH 用户，但不能满足直接运行二进制的要求。
- **所有系统共用一个可执行文件：**原生运行时不兼容，需要各目标独立构建和分发。
- **单文件自解压包：**目录包更便于检查依赖布局和 worker 启动，便携压缩包已提供
  单个下载文件。
- **自动发布 Release：**先生产并验证产物，正式发布是独立操作。

## 后果

每个包携带运行时，体积更大。原生安装器工具仅构建机需要。便携执行文件必须保留全部
随附文件。安装包没有发布者签名证书或 Apple 公证。Windows 的 `watch` 仍因 Unix
文件锁暂不支持，峰值 RSS 指标也仍不可用。

## 验证与风险

每个构建须验证版本/帮助、多 worker 索引 C 夹具、查询结果、stdio MCP
initialize/tools，以及桌面网页/API 与 HTTP MCP。四个原生目标已基于源码 `d7d0f8`，
在[运行 39253506257](https://github.com/yushun667/CA/actions/runs/39253506257)通过
构建及安装后二进制冒烟检查，产物/校验和可下载。全仓测试基线仍有失败。
更早系统版本与额外架构需要单独验证。原生包不替代源码项目的编译数据库、头文件或
编译器 sysroot。
