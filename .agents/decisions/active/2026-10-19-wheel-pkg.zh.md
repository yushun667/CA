# 决策：用 wheel + 离线 wheelhouse 安装 CA

Status: active
Date: 2026-10-19

## 背景

插件最初要求用户自备 CA checkout 与 venv，或把 checkout rsync 到远程 Linux 主机后
editable 安装，因为 `pyproject.toml` 没有声明 package-data：构建出的 wheel 会静默遗漏
`src/ca/store/schema.sql` 与 UI 静态资源。这隐含要求每台后端主机都有 Python 工具链、
PyPI 网络、`rsync` 与可写源码树——对 DSH 桌面用户和隔离网络服务器都不成立。新用户
应当无需构建步骤即可用起来。

## 决策

- 让 Python 包 wheel-complete：声明 package-data（`ca.store` schema 与 `ca.ui` 静态
  文件）、补 `MANIFEST.in`，构建 `ca_analyzer-<version>-py3-none-any.whl` 并内置到
  插件 `dsh/backend/wheels/`（约 360 KB）。
- 默认从该 wheel 安装后端，支持本地（Windows/macOS/Linux）与远程 Linux：创建私有
  venv、`pip install` 该 wheel（在线依赖来自 PyPI）、`ca version --json` 校验。旧的
  rsync + editable 源码流程只保留为 `mode:'source'`/开发者回退。
- 增加离线路径：`dsh/scripts/build-wheelhouse.mjs --platform <id>` 按平台构建依赖
  wheelhouse（`linux-x64`/`arm64`、`macos-arm64`/`x64`、`windows-x64`，约 41–46 MB）
  到 `artifacts/wheelhouse/<platform>/`；pip 用 `--no-index --find-links` 安装。
  远程离线安装通过 scp（或 ssh 上的 tar 流）上传 wheelhouse。
- 前置要求 Python >= 3.11（Windows 探测 `py -3.13/3.12/3.11`，其他平台探测
  `python3.13/3.12/3.11`；以 `UNSUPPORTED_PYTHON` 提前失败）。
- 把最近一次成功安装摘要持久化到 `install-state.json`（0600），经
  `backend.get.install` 与 `backend.installStatus` 暴露；后端页负责 Install/Repair
  以及在线/离线、wheel/source 的选择。

## 原因

- wheel + wheelhouse 让安装确定、可离线、平台显式；安装期不编译任何东西。
- 把 CA wheel 内置进插件可保持插件与被分析的包版本一致，并去掉 registry 依赖。
- wheel-complete 打包同时修好了其他任何基于 wheel 的 `ca serve`/`ca ui` 安装，不只
  服务本插件。
- Python 3.11 是项目声明的最低版本；在 pip 之前探测能给出可操作的错误，而不是晚期
  失败。
- 保留 source 模式可控制风险：既有开发者部署与调试流程继续可用。

## 考虑过的替代方案

- **只保留 editable 安装**：否——每台主机都需要 checkout、工具链与网络，Windows/
  隔离网络服务器无法使用。
- **发布 CA 到 PyPI 后从索引安装**：否——把插件绑到发布流程与 registry 可用性上，
  且离线安装不可能。
- **内置 virtualenv/zipapp**：否——平台相关且体积大；wheel 才是标准、可审计的产物。
- **只发一个“全平台”wheelhouse**：否——依赖 wheel 分平台；构建器会按目标 pip tag
  校验。
- **保留远程 source/rsync 为默认**：否——`rsync` 与可写 checkout 正是远程安装的主
  要失败来源。

## 后果

- 新安装走后端页 **Install / repair**：在线只需网络；离线需要为目标平台生成一次
  wheelhouse。
- 插件携带二进制产物（`dsh/backend/wheels/`），`package.json` 的 `files` 含
  `backend/**`，因此安装插件会复制该 wheel。
- Windows 代码路径已实现但未真机验证，且 CA `watch` 在 Windows 不可用；远程后端只
  支持 Linux。
- 离线 `.tar.gz` 包在本地 `pip --find-links` 前必须先解压。
- 实测：macOS arm64 本地离线安装约 1.4 s；真实 Linux 服务器离线 wheel 安装约 6.4 s
  （含 46 MB wheelhouse 上传）。

## 验证与风险

单元/契约测试覆盖平台 id、Python 探测、安装步骤状态机、上传策略与安装状态合并；
真机验证覆盖 macOS arm64 与 Linux 服务器。风险：依赖 wheel 必须匹配目标平台与
Python ABI；不同 pip 版本生成 wheelhouse 的行为有差异；内置 wheel 必须与
`pyproject.toml` 保持同步；Windows 路径仍未验证。
